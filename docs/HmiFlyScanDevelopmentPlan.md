# PLC HMI 与飞拍软件开发及验收计划

适用于同一 Prism 工程下分别安装的 PLC HMI 和飞拍软件。首个可交付成果是两个独立宿主加载同一份 IO 页面，分别显示 PLC 测试数据和运动卡仿真数据。最终交付以两款软件各自的发布包和验收记录为准。

## 责任与放行规则

- 开发负责人对实现、自动测试和构建记录负责。复核人根据用例和原始记录登记阶段结论。工艺负责人确定拍摄质量、位置和时间指标，设备调试负责人执行实卡测量。人少时可以兼任角色，记录中写明实际执行人和复核人。
- 每个阶段按“待开发、待验证、通过、失败、阻塞”记录。所有必测项须有预期、实测结果和可找到的证据，方可标记通过。缺设备、缺约定或未执行的必测项记阻塞，只阻塞有依赖的阶段。HIL 指在目标硬件上执行的验证。
- 每次提交只迁移一个页面或一项设备能力。合并前运行架构检查、受影响的自动用例及既有 PLC HMI 回归。涉及共享契约、权限、停止和退出路径的变更，两个宿主均须复验。候选发布版本执行完整矩阵。
- 错误设备动作、失效联锁、漏发或多发触发、未知反馈被显示为完成、产量重复入账，任一项均阻止相应产品放行。离线构建要求零错误，按警告代码、项目和触发行对照 G0，新增警告须修复或有具名复核结论。失败记录须关联修复版本，并重跑原用例、同一路径的异常用例以及受影响的下游验收。

| H2 实机异常及恢复 | 在受控台架、经确认的工况下复测 F2 中与实机相关项，记录停稳、触发撤销、任务清理；再从已确认状态开始新组 | 超时和卡掉线可见，接收停止命令后以反馈确认结果。按预定边界核对在途脉冲和后续输出。恢复后第一次扫描的触发清单完整，旧任务与下一组无串扰 |

F1 的离线重复性门槛定为连续 100 次双组扫描，完成件只按测试配方定义的完成事件累计。每个 F2 场景至少覆盖一次中断和一次重新开始，保留可重放的输入序列。发生竞争的用例至少覆盖事件的两种先后顺序。100 次用于本计划的软件回归，实机重复次数及工况须按下节冻结。

G2 须逐项核对八个状态值，包括0 停止、10 故障、20 暂停、30 调试、40 初始化、50 运行、60 维护任务、70 急停。退出、暂停与恢复策略属于产品业务。流程负责人在 G3 建立“当前步骤、输入事件、期望状态、触发处理、恢复条件”表，后续可随 C# 时序一起版本化。

## 实机测量和计数口径

1. 在正式验收前冻结机型配置、配方、驱动和固件版本。工艺及调试人员填写 X/Y 触发位置误差（mm）、R1 角度误差（°）、R2 相对 R1 的位移和速度误差、脉冲极性与宽度、采样分辨率、响应时间、速度范围和样本数。每项应有数值、单位、测量方法和负责人。空项记为待确认。
2. 分别构造只改变 X、Y 或 R1 的反例。例如固定 X、Y，让 R1 从错误角度经过，只在完整目标条件满足时允许产生对应边沿。覆盖相邻目标、不同速度、往返路径和起始相位偏差。测试前写明预期边沿序号及允许位置窗口。
3. 将目标清单、编码器轨迹及独立测得的输出波形按同一时基对齐，逐点核对位置、顺序和边沿总数。用两轴各自起点计算 ΔR2 − ΔR1，分别检查加减速、匀速、暂停与恢复。起始机械角度可以不同。
4. 扫描 Ready 信号由视觉提供，触发信号由卡输出。电气验收以实际边沿为证据。如需证明实际成像，使用视觉软件独立导出的记录对时。完成工件数量取自经确认的业务完成事件。
5. 现场试验使用计划内的台架与操作流程。若目标硬件的比较维数或输出资源不足，登记受影响的配方和工况，实机阶段保持阻塞并评审替代方案。单轴比较和上位机轮询均不能作为本版多坐标验收通过的依据。
