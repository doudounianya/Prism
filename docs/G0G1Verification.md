### 飞拍主卡与流程 IO

主卡 `IMC-SIM-01` 的第 0 组显示流程使用的仿真握手。第 2 台仿真卡仍可独立验证分组和断线。通道编号仅用于离线仿真。

| 方向 | 仿真通道 |
| --- | --- |
| DI 00–05 | 上料确认、机器人到位并保持、视觉 Ready、下料确认、告警、急停 |
| DO 00–04 | 上料请求、机器人示教位请求、机器人保持请求、视觉触发、下料请求 |

主卡断开后，IO 当前值与模式反馈均进入未知状态，上次有效值单独显示。正在运行的扫描撤销保持和触发并等待恢复。重连读取新的 IO 快照，操作员确认后才恢复扫描。切换 IO 页面、设备或分组只读取快照。

### 两套宿主使用同一组 IO 样本

完整离线复跑使用同一个 [DI、DO 测试样本](../tests/Fixtures/SharedIoFixture.json)。PLC HMI 从本机 OPC UA 服务读取，飞拍从仿真主卡适配器读取。每个方向逐行核对 16 个通道的逻辑地址、ON/OFF、数据质量、时间显示、绑定信息和未配置状态，并核对统计点数。断线时核对当前值与历史值分开显示，重连后用新样本再测。两个日志都记录样本 SHA-256。

飞拍页面在采集时记录主卡连接代次。主卡断开或重连使旧代次失效，迟到快照无法覆盖当前值或历史。PLC 回环用例继续验证其原有连接代次门槛和实际写入记录。飞拍界面同时覆盖第二台仿真卡和分组切换。

2026-11-25 飞拍共享 IO 通过 25 项断言，PLC OPC UA 回环通过 58 项断言，完整离线复跑 28 项全部通过。在隔离源码副本中移除飞拍代次校验后，迟到的 DO 快照触发预期失败。 样本、日志和复跑记录（本地归档 `2026-11-25-shared-io-sample-replay.zip`）

### PLC HMI 双设备切换

统一复跑在隔离工作簿中为 PLC01、PLC02 配置不同的本机 OPC UA 端口。PLC02 仅启用只读 DI、DO，使用与 PLC01 相同的逻辑地址和不同的位值。启动前由正式工作簿加载器校验两个端点和绑定范围。

在共享 IO 页切换设备后，逐项核对状态和详情归属。断开 PLC02 时，画面保留其历史值并将当前值标为未知。切回 PLC01 仍从原连接读取实时值。PLC02 重连后核对新连接的 DI、DO，两个回环服务记录的切换及重连写入为零。
