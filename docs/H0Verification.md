# H0 汇川 IMC30G-E 离线核验

验证日期为 2026-11-24。本轮检查项目配置、磁盘上的 x64 SDK 文件和轨迹判定逻辑。实机验收状态为待验证。

## 板卡资料与项目配置

- 随项目分发的 SDK 1.8.29.4 和厂商资料中的 SDK 1.8.30.7 分别有 1368 和 1378 个具名导出。两份文件均包含核验所需的身份与资源、三维位置比较、电子齿轮接口。检查直接读取 DLL 文件，SDK 版本和导出结果仅说明文件中有哪些接口。
- [13 轴配置](../examples/Motion/FlyScan.13Axes.json) 的 Localbus 轴号为 0–3，EtherCAT 轴号为 4–12。`Front.Scan` 包含 `X/Y/R1`。`R2` 使用 `R1` 的指令位置作为跟随源，以工程单位按 1:1 跟随。验收比较两个旋转轴各自从起点算起的角位移和角速度，允许各自的起始角和编码器当量不同。
- 随机资料中的 C02 软件编程手册 §7.6 把三维比较的逻辑端口 4、5、位置源通道和 `PWM`、`CMP`、`EX-O` 实际输出分别配置。需现场记录比较维数的读回值、对应的三个位置源及实际接线。换算位置比较参数时要按手册使用对应的脉冲当量。电子齿轮参数和状态读回见 §10.5。IMC30-6G 硬件手册 PDF 第 11 页说明相关 Localbus 端子资源。
- 驱动在已读回资源且缺少端子板时将标准位置比较报告为 `Unsupported`。检测到端子板时仍报告 `Unknown`，直到实际比较维数、位置源和输出得到验证。当前版本的位置比较和电子齿轮均未开放实机执行。

## 重放命令

在解决方案根目录使用 Python 3.11 或更高版本运行。

```powershell
python tools/verify_flyscan_h0.py
python -m unittest discover -s tests -p 'test_flyscan_h0.py' -v
python tools/verify_flyscan_h0.py --bench examples/Motion/FlyScan.IMC30G.H0.example.json --require-bench
```

默认检查随项目分发的 SDK。可重复传入 `--sdk` 检查其他 DLL，用 `--out` 保存 JSON 报告。第三条命令对空白模板返回 `pending` 和退出码 `2`。数据或判定失败返回退出码 `1`。完整实测数据通过自动检查时返回 `readyForReview`，由复核人员核对原始记录、工艺限值和设备配置后签收。

## 台架记录与轨迹判定

[台架记录模板](../examples/Motion/FlyScan.IMC30G.H0.example.json) 预留了设备型号、固件、模块型号与版本、实际通道、脉冲宽度、位置及同步限值。限值由工艺确认后填写。四组原始证据分别记录硬件和配置、编码器、触发输出、齿轮状态，文件路径相对于记录目录并附 SHA-256。通过哈希核对后，由复核人员把转录数据与原始文件逐项比对。

编码器样本采用 `[时间毫秒, X 毫米, Y 毫米, R1 度, R2 度]`。触发边沿采用 `[时间毫秒, "rise" 或 "fall"]`，与编码器记录使用同一时间基准。工具按约定的有效高脉冲检查，上升沿为触发时刻。

| 用例 | 自动判定 |
| --- | --- |
| `forward`、`reverse` | 每条扫描至少有两个目标。检查 X/Y/R1 的联动样本、触发数量和顺序、触发时插值得到的三轴坐标、脉冲宽度，以及 R2 相对 R1 的角位移误差与各采样间隔内的平均角速度差 |
| `rejectX`、`rejectY`、`rejectR1` | 另外两个坐标达到目标容差，被考查的单轴超出容差时，未观察到触发 |
| `gearExit` | 状态读回确认齿轮退出后，R1 产生位移，R2 在允许误差内保持原位，且未观察到触发 |
