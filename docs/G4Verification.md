# G4 共用业务页面与历史验收

验证日期为 2026-11-24。Codex 在 Windows 隔离目录执行仿真和回归。PLC HMI 使用回环 OPC UA 设备和从 G0 恢复的专用 MySQL 副本。飞拍使用独立的本机 SQLite 历史库。

## 页面与数据边界

- 两个宿主复用设备监控、实时报警、历史报警、报警分析、今日产量、生产日报、产量趋势和操作日志的 WPF 页面。工艺参数共用工作区，飞拍保留手动示教和双组时序，PLC HMI 保留原工艺字段与权限。系统设置共用页签和布局，各自填充软件及账户内容。
- 飞拍顶部有十个既定入口，原 MES 入口保持禁用。飞拍系统设置显示当前仿真身份和本机数据目录，PLC 保留原账户服务和可编辑软件设置。
- 只有飞拍仿真写入同一用户目录下的 `history.sqlite`。源数据由实际经过的飞拍时序和仿真信号提供。G3 已完成的累计次数保留，G4 按完成时间建立历史；旧检查点缺少日期的累计值不回填到班次。

### 检查点和完工入库失败

- 在比较点和下料确认分别阻止替换检查点文件。流程撤销输出并保留可读的旧检查点，未提交的动作不增加计数。文件恢复后仍须显式确认恢复，下料阶段的重试保留两个已完成组。
- 在 SQLite 完工事务写操作日志时注入失败。工件表和操作日志一并回滚，已完成的检查点保留原工件 ID 和确认时间。存储故障持续期间，下一件不能覆盖这份检查点。
- 历史库可写后，空闲流程按间隔自动重试完工入库。WPF 关闭自动步进并切到生产数据页时，也能补写并显示一件工件。补写沿用确认时的班次，重启后仍只有一条完工记录。

2026-11-25 飞拍流程共通过 90 项断言。注入完工入库失败后，将重试时间推进到北京时间 20:00 之后，产量仍计入工件在 19:59:59 确认时的白班。 存储恢复验证记录（本地归档 `2026-11-25-flyscan-storage-retry.zip`）

### 报警观测写入失败

- 报警状态记录或心跳写入失败时，实时报警反馈标为未知，保留最后一次成功落盘的时间。下一条成功落盘的采样重新建立实时反馈。
- 历史查询将两次成功采样之间未经确认的区间保留为采集缺口。用固定时钟分别注入状态记录失败和心跳写入失败，两种情况下的报警有效时长均为 3 秒，另有 2 秒未知区间。关闭并重新打开历史库后，按同一口径查询。
