# G3 飞拍示教、配方和双组流程验收

验证日期为 2026-11-24。飞拍运行在运动卡仿真、可控时钟和输入输出替身环境中。PLC HMI 回归使用回环 OPC UA 服务、恢复的隔离 MySQL 测试库及专用配置。Codex 执行并核对离线结果。

## 操作入口

1. 启动 `Company.FlyScan.Shell`，打开「飞拍工艺 → 手动示教与配方」。设备工程师、工艺工程师或管理员可在手动调试状态下新建配方。到轴参数页点动或定位，停稳后记录每组的起点、轨迹点和触发点。机器人示教器保存拍摄位置，配方只保存位号。
2. 保存配方为 JSON，也可用「载入示例」打开随程序提供的双组配方。示例位号为 P01/P02。配方包含两个组，每组的触发点可位于指定插补段内或段终点，保存时校验 X、Y、R1 是否同时落在该段，以及触发顺序是否正确。
3. 将仿真反馈切到「自动模式／停止」，打开「双组流程仿真」后开始。可以自动步进，也可单步检查上料、机器人到位保持、视觉 Ready、运动卡连线和下料输入。撤销信号可复现中断，修复输入并确认工件状态后使用「确认恢复」。

## 时序与恢复

机器时序在 [FlyScanWorkflow.cs](../Applications/FlyScan/Company.FlyScan.Runtime/FlyScanWorkflow.cs) 的 `RunCurrentStep`，配方约束在 [FlyScanRecipe.cs](../Applications/FlyScan/Company.FlyScan.Runtime/FlyScanRecipe.cs)。共用 WPF 页面及实卡驱动沿用现有入口。

| 当前步骤 | 输入条件 | 动作与确认 |
|---|---|---|
| 等待上料 | 上料确认对应当前请求及工件 | 发送本组机器人示教位请求 |
| 等待机器人 | 当前请求位号匹配、到位且静止 | 保持该位，等待视觉 Ready |
| 等待 Ready／平台定位 | 机器人持续到位且 Ready 为 ON | 平台定位到本组起点，定位期间触发关闭 |
| 连续扫描 | 机器人持续保持且 Ready 持续为 ON | 单次提交整组 XYR1 直线轨迹。仿真按实际走过的轨迹段比较三维坐标，按顺序输出脉冲，并检查 R2 相对 R1 的位移与速度 |
| 组确认 | 位置终点到达，触发清单完整，机器人和 Ready 仍有效 | 确认本组后切到下一机器人示教位。第二组确认后请求下料 |
| 等待下料 | 下料确认对应当前请求及工件 | 工件结算一次。工件、确认组、触发脉冲分别累计 |
| 中断／恢复 | 取消、暂停、停止、反馈失效、超时、告警、急停或重启 | 取消触发并清理轨迹，反馈未知时保持等待清理。记录最后确认触发。确认恢复后保留已完成组，将未完成组从起点重做。重做产生的脉冲按实际仿真脉冲累计，已确认的组和工件不重复结算 |

检查点默认位于当前用户本地应用数据目录的 `Company/FlyScan/Simulation/run.json`，同时保存工件标识、配方快照、最后确认点和累计计数。重启后先进入中断状态，用户需要核对当前工件并确认恢复。视觉侧仅模拟 Ready 和触发，脉宽 2 ms 是离线假设。机器人和上下料的握手标识用于仿真内区分新旧请求，现场 IO 地址、触发精度和脉宽须由实卡阶段验证。

### 触发与中断的先后顺序

- 在第一个比较点之前撤销 Ready，扫描立即中断，工件、组和脉冲计数均为 0。先产生上升沿再撤销 Ready 时，保留这一次已发出的上升沿，轨迹的下降沿按实际撤防时间记录。两种顺序都需要显式确认才能重做未完成组。
- 后一个比较点恰好与前一脉冲的下降沿重合时，流程按位置比较异常中断，只保留第一个脉冲。两者之间有仿真低电平间隔时，记录两次独立的上升沿。
- 组确认与告警分别按两种顺序复跑。先收到告警时需要重做该组，已经确认的组在恢复时保留。两条路径最终均结算同一工件一次。

回归使用确定的仿真时间步，保留输入顺序和实际脉冲记录。流程冒烟共 76 项通过，包含连续 100 次双组扫描。实际脉宽与有效低电平间隔仍由 H0 和 H1 按台架波形验证。 触发边界验证记录（本地归档 `2026-11-25-flyscan-trigger-boundaries.zip`）

### 仿真轴控制权与权限切换

- 检查点成功保存后才发布运行反馈。开始或恢复通知期间撤权、反馈变为未知时，旧流程立即收起上料、机器人和触发请求，后续时间步中断同一工件。
- 每条扫描路径由取得控制权的流程清理。中断后已经释放控制权的流程无法撤销另一工件正在执行的路径。断线时清理若未确认，手动调试保持只读，控制权仍留给等待清理的流程。
- WPF 在扫描中切换到手动调试时撤销触发与机器人保持，确认停稳后开放手动控制。切回自动后，原工件等待操作员确认恢复。

2026-11-25 飞拍流程 102 项、共享桌面 69 项断言通过。测试记录包含通知期间撤权、过期流程申请恢复、断线清理和关闭释放轴的实际输出。 轴控制权验证记录（本地归档 `2026-11-25-flyscan-motion-ownership.zip`）

### 仿真上下料握手恢复

- 上料和下料每次请求使用各自的握手号。反馈需要同时对应当前请求和工件。中断后确认恢复或重新打开检查点时，等待中的上下料请求使用新握手号，工件 ID 沿用原记录。
- 回放分别在等待上料和等待下料时注入前一次请求的回执。旧回执不能推进流程。新的下料回执确认后只结算一次，同一工件已完成的扫描组保留。

2026-11-25 覆盖等待上料和下料各两种恢复情形，飞拍流程通过 121 项断言。完整离线复跑通过 26 项检查，包括飞拍仿真跨版本恢复和 PLC HMI 回归。 上下料握手验证记录（本地归档 `2026-11-25-flyscan-transfer-handshake.zip`）

### 扫描途中进程终止及恢复

`FlyScan.Workflow.Smoke` 每次运行会启动两个独立的仿真进程。第一组完成、第二组第一个脉冲写入检查点后，测试终止第一个进程。第二个进程读回同一工件、已确认组和最后触发点，在健康输入恢复后仍保持中断且无输出。显式确认恢复后只重做第二组，检查触发点及其顺序，并核对 SQLite 中只有一条同工件的完成记录。

单独运行冒烟测试时可传入新证据目录。统一复跑将阶段报告、两个进程日志、终止前检查点和完成记录写入 `workflow/process-restart`。

2026-11-25 仿真进程终止时为 0 件、1 组、4 次触发。新进程先恢复到中断，确认恢复后完成同一工件，总计 1 件、2 组、6 次触发。飞拍流程 136 项断言、正式工程完整离线复跑 28 项检查全部通过。 进程重启验证记录（本地归档 `2026-11-25-flyscan-process-restart.zip`）

### 第一组时序独立修改演练

在已核验飞拍仿真包的隔离副本中，只替换飞拍业务运行库。演练版让第一组在机器人到位保持后至少等待 120 ms，再在 Ready 有效时启动定位或扫描。第二组沿用原时序。

实测第一组离开等待从 1 个 50 ms 单步变为 3 个，第二组仍为 1 个单步。两次运行各完成 1 件、2 组、5 个脉冲，触发顺序、坐标和脉宽相同。桌面宿主、共享页面和仿真驱动沿用候选包中的二进制，两次共享桌面用例各通过 80 项断言。

记录内含最小 C# 改动、复跑入口和两次桌面验证结果。解包后可在正式工程目录运行其中的 `verify_workflow_timing.py`，传入 `--source .`、`--candidate <已核验飞拍候选包>` 和 `--output <新目录>`，离线可另加 `--restore-source`。
